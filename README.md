## 这是什么

一套**双机 LoRa 无线传感器监测系统**，由两块 STM32F103ZET6 板子组成：

| 角色 | 职责 |
|---|---|
| **从机（发送端）** | 采集雨滴传感器 + 水位传感器 + DHT20 温湿度，组 ASCII 帧，**每秒**经 LoRa 发出 |
| **主机（接收端）** | 接收 LoRa 数据帧，拼帧解析，**每 10 秒**刷新 OLED 显示，水位 **> 70%** 时立即蜂鸣报警 |

两块板子之间**没有任何线缆连接**，全靠 470MHz LoRa 无线通信。

## 系统架构

```
┌──────────────────────────────────────┐
│  从机 STM32F103ZET6                   │
│                                      │
│  雨滴传感器  PC1(DO) / PC2(AO)        │
│  水位传感器  PA1(AO)                  │
│  DHT20      PB6(SCL) / PB7(SDA)      │
│                    │                 │
│                    ▼ 组帧             │
│  LoRa TX ──► USART3 (PB10/PB11)      │
│                    │                 │
│                    └──► USART1 ──► PC 串口调试
└────────────────────┼─────────────────┘
                     │
              ~470MHz 无线（LoRa）
                     │
┌────────────────────┼─────────────────┐
│                    ▼                 │
│  LoRa RX ──► USART3 (PB10/PB11)      │
│                    │                 │
│                    ▼ 拼帧 + 解析      │
│  主机 STM32F103ZET6                   │
│                    │                 │
│         ┌──────────┼──────────┐      │
│         ▼          ▼          ▼      │
│   OLED(PB6/PB7)  蜂鸣器(PB8)  串口调试 │
│   10 秒刷新      超限报警     USART1  │
└──────────────────────────────────────┘
```

### 数据流

```
传感器 ─► 采集 ─► 组帧(ASCII) ─► LoRa ─► 拼帧 ─► 校验 ─► 解析 ─► OLED/蜂鸣器
```

## 核心特性

### 从机

- **三路传感器**：雨滴（DO 数字量 + AO 模拟量）、水位（AO）、DHT20 温湿度
- **每秒上报**（`REPORT_INTERVAL_MS = 1000`）
- **ASCII 文本帧**，对端串口助手可直接阅读，无需解析二进制
- **带校验和**（累加和取低 8 位，两位大写 HEX）
- 本地串口同步打印中文数据，便于现场调试

### 主机

- **流式拼帧器** —— 解决 LoRa 模块把一帧拆成 32 字节碎片的致命问题
- **10 秒刷新**（`OLED_REFRESH_MS = 10000`）—— 数据实时，显示节流防闪烁
- **水位 > 70% 立即报警** —— 蜂鸣器 + OLED 显示"水位过高"，**不遵循**刷新周期
- **断线保护** —— 5 秒无数据自动清报警、关蜂鸣器、显示"等待从机"

---

## 三个关键设计取舍

| 约束 | 内容 | 带来的设计 |
|---|---|---|
| **协议** | LoRa 模块只有 256 字节 FIFO，且会按 32 字节分块吐数据 | 帧长控制在 71~79 字节；主机必须做**流式拼帧**，不能把每次 IDLE 中断收到的数据当一帧 |
| **显示** | OLED 频繁刷新会闪烁，但数据要实时 | **数据与显示解耦**：数据每秒更新到内存，屏幕每 10 秒渲染一次；报警作为例外立即渲染 |
| **报警** | 水位超限必须立刻知道，不能等刷新周期 | 检测报警状态**跳变**（边沿触发），跳变瞬间立即刷屏 + 立即鸣叫 |

## 快速开始

### 1. 硬件准备

| 项 | 从机 | 主机 |
|---|---|---|
| 主控板 | STM32F103ZET6 开发板 | STM32F103ZET6 开发板 |
| 无线模块 | AS32-TTL-100-C × 1 | AS32-TTL-100-C × 1 |
| 传感器 | 雨滴 + 水位 + DHT20 | 无 |
| 显示 | 无 | 0.96" SSD1306 OLED |
| 其他 | 蜂鸣器（板载） | 蜂鸣器（板载） |

> **两块 LoRa 模块的地址、信道、空中速率必须完全一致**，否则收不到。
> 本工程统一配置：地址 `0x0000` / 信道 `0x3D`(471MHz) / 9600 8N1 / 2.4k / 透明传输。

### 2. 编译

用 Keil MDK 打开对应工程，按 **F7**：

```
code/slave/project/STM32F103ZET6_Project.uvprojx     ← 从机
code/master/project/STM32F103ZET6_Project.uvprojx    ← 主机
```

或命令行：

```powershell
# 从机
& 'C:\Keil_v5\UV4\UV4.exe' -b 'code\slave\project\STM32F103ZET6_Project.uvprojx' -j0 -o build_slave.log

# 主机
& 'C:\Keil_v5\UV4\UV4.exe' -b 'code\master\project\STM32F103ZET6_Project.uvprojx' -j0 -o build_master.log
```

**编译状态**（已验证）：

| 工程 | 结果 | Code | RO-data | HEX |
|---|---|---|---|---|
| 从机 | **0 Error / 3 Warning** | 12078 B | 498 B | 35585 B |
| 主机 | **0 Error / 3 Warning** | 10610 B | 122206 B | 373712 B |

> 3 个 Warning 均来自 `i2c.c` 的 `0x0F << 28` 整数溢出，是标准库示例代码遗留，不影响功能。
> 主机的 122KB `RO-data` 是 GB2312 汉字字库（3755 字），用于 OLED 显示中文。

### 3. 烧录

两块板子分别烧录对应 HEX：

```
code/slave/project/Objects/STM32F103ZET6_Project.hex
code/master/project/Objects/STM32F103ZET6_Project.hex
```

### 4. 验证

**从机串口**（9600 8N1，**编码选 GBK**）每秒输出：

```
温度:26.4℃,湿度:49.6%,无雨,水位:80%(ADC=716)
温度:26.5℃,湿度:52.2%,无雨,水位:80%(ADC=689)
```

**主机 OLED** 每 10 秒刷新：

```
温度:26.5
湿度:52.2
水位:80%
无雨
```

水位超过 70% 时**立即**变成：

```
温度:26.5
湿度:52.2
水位:75%!
水位过高
```

同时蜂鸣器发出"哔—哔—"间隔报警声（每 500ms 翻转）。

## 硬件接线速查

### 从机

| 功能 | 引脚 | 备注 |
|---|---|---|
| 雨滴 DO | **PC1** | 上拉输入，1=无水 0=有水 |
| 雨滴 AO | **PC2** | ADC1_IN12 |
| 水位 AO | **PA1** | ADC1_IN1，**必须拔 P10 跳线帽** |
| DHT20 SCL | **PB6** | 软件 I2C，需 4.7K~10K 上拉 |
| DHT20 SDA | **PB7** | 软件 I2C，需 4.7K~10K 上拉 |
| LoRa | PB10/PB11/PB12/PB13/PB14 | USART3 + MD0/MD1/AUX |
| 调试串口 | PA9/PA10 | USART1 9600 8N1 |

### 主机

| 功能 | 引脚 | 备注 |
|---|---|---|
| OLED SCL | **PB6** | 软件 I2C，需 4.7K~10K 上拉 |
| OLED SDA | **PB7** | 软件 I2C，需 4.7K~10K 上拉 |
| LoRa | PB10/PB11/PB12/PB13/PB14 | USART3 + MD0/MD1/AUX |
| 蜂鸣器 | **PB8** | 推挽输出 |
| 调试串口 | PA9/PA10 | USART1 9600 8N1 |

> 注意：从机 PB6/PB7 接 **DHT20**，主机 PB6/PB7 接 **OLED**。两台板子各自独立，不冲突。

详细接线与注意事项见 [docs/硬件接线.md](docs/硬件接线.md)。

## 通信协议速览

从机每秒发出一帧 **ASCII 文本帧**：

```
$RAIN,DHT20,T=26.5,H=52.2,ADC=4092,V=3297,WET=0,DO=1,LEVEL=0,WL=80*8B\r\n
```

| 字段 | 含义 |
|---|---|
| `T=` | 温度 ℃（DHT20 失败时 `--`） |
| `H=` | 湿度 %RH（失败时 `--`） |
| `ADC=` | 雨滴 AO 原始 ADC 值 0~4095 |
| `V=` | 雨滴 AO 电压 mV |
| `WET=` | 雨滴湿润百分比 0~100 |
| `DO=` | 雨滴数字量 1=无水 0=有水 |
| `LEVEL=` | 雨情等级 0=无雨 1=小雨 2=中雨 3=大雨 |
| `WL=` | **水位百分比 0~100** |
| `*XX` | 校验和：`*` 之前所有字节累加取低 8 位，两位大写 HEX |

完整协议说明见 [docs/通信协议.md](docs/通信协议.md)。

## 已修复的关键问题

这些问题都是实际调试中踩到的，文档里有完整记录，**改动时勿回退**：

| 问题 | 现象 | 根因 | 修复 |
|---|---|---|---|
| **LoRa 帧被拆成碎片** | 主机屏幕一直 `温度:--` | 模块按 32 字节分块吐数据，每次 IDLE 当一帧解析必然失败 | 新增 `frame_assembler.c` 流式拼帧 |
| **拼帧器垃圾堵塞** | 碎片能拼但偶发卡死 | 缓冲残留垃圾等不到换行，堵死后续正常帧 | 缓冲内无 `$` 即清空重同步 |
| **水位没水也报 9mm** | 干燥时一直显示 9mm | 噪声落进 10% 档，10%×90mm=9mm | 加 `LEVEL_IGNORE_BELOW_MM` 死区 |
| **报警要等 20 秒** | 水位超限后迟迟不显示 | 只标脏不立即刷屏 | 改边沿触发，跳变立即刷屏 |
| **断线蜂鸣器长响** | 断线后一直响 | `waterAlarm` 保持旧值 | 超时分支清报警 + 关蜂鸣器 |
| **串口 3 次调用白等 150ms** | 主循环卡顿 | 单一 DMA 缓冲，连续调用互相等待 | 拼成一个缓冲一次发出 |
| **`s_txLine` 超 DMA 上限** | 日志被静默截断 | 272 > 256 | 缩到 240 + 双重上限检查 |
| **OLED 汉字不显示** | 显示方块/乱码 | `OLED_USE_FONT = 0` 字库未编译 | 改为 1 |
| **`oled.h` 引用不存在的头** | 编译报错 | 移植残留 `#include "usart.h"` | 删除 |
| **缺 `OLED_ADDR` 等宏** | 编译报错 | 宏原本在丢失的 `usart.h` 里 | 补进 `i2c.h` |

## 已知限制

| 项 | 说明 |
|---|---|
| **单向下行** | 从机→主机单向数据流；主机可发数据但当前固件未用于控制从机 |
| **无应答重传** | 透明传输模式，丢帧不重传。主机靠校验和丢弃坏帧，下一帧（1 秒后）自然补上 |
| **无时间戳** | 帧内不含时间，主机不判断数据新鲜度（靠 5 秒超时兜底） |
| **水位量程固定 90mm** | 门限表按 90mm 量程标定，换传感器需重新标定 |
| **主机的 `sensor_report.c` 等文件** | 从机代码的副本，主机不使用，保留以维持工程结构一致 |
