## 2 从机参数详解

### 2.1 上报周期 `REPORT_INTERVAL_MS`

```c
/* sensor_report.h */
#define REPORT_INTERVAL_MS (1000)   /* 1 秒 */
```

**约束**：不能低于 **500ms**。

**耗时构成**：

| 环节 | 耗时 |
|---|---|
| 雨滴 AO 采样 | ~1 ms |
| 水位采样 | ~2 ms |
| DHT20 测量 | ~100 ms |
| LoRa 发送 71B @9600 | ~74 ms |
| **合计** | **~200~250 ms** |

1 秒周期余量 750ms，安全。低于 500ms 时 DHT20 会来不及，帧内容开始异常。

**改大**：省电、降低 LoRa 占用（如 `5000` = 5 秒）
**改小**：更实时（但不要低于 500）

> **注意**：主机刷新周期（10 秒）与本参数**独立**。
> 从机发得再快，主机也是 10 秒刷一次屏（报警例外）。

### 2.2 水位噪声死区 `LEVEL_IGNORE_BELOW_MM`

```c
/* level.h */
#define LEVEL_IGNORE_BELOW_MM (9)   /* 9mm */
```

**作用**：高度 ≤ 此值时强制归零，消除干燥噪声误报。

**原理**：

```
传感器干燥 → ADC 在 160~189 抖动
           → 落进门限表最后一档（≥160 → 10%）
           → 10% × 90mm = 9mm
           → 显示"水位:9mm"（实际没水）
```

加死区后：`height ≤ 9` 时强制 `height = 0; percent = 0;`

**调大**：死区更宽，更不容易误报，但低水位会丢失
**调小**：能测更低水位，但可能误报

| 值 | 忽略的 ADC 范围 | 效果 |
|---|---|---|
| 9（当前） | 160~189 | 忽略整个 10% 档 |
| 18 | 160~219 | 忽略 10% + 20% 档 |
| 0 | 无 | 关闭死区（不推荐） |

**判断依据**：看从机串口的 `(ADC=xxx)`。
如果干燥时 ADC 稳定在 200 以上还误报，说明噪声更大，需要调大死区。

### 2.3 水位量程 `LEVEL_RANGE_MM`

```c
/* level.h */
#define LEVEL_RANGE_MM (90)   /* 90mm */
```

**作用**：100% 对应的物理高度。

**改这个参数时**：门限表 `level_threshold[]` 不用改（它是 ADC 阈值，与量程无关），
但 `Level_AdcToHeight()` 的输出会按新量程缩放。

> 当前固件**显示的是百分比**（`WL=` 字段），高度值不再上报。
> 量程主要用于内部换算，改它不影响主机显示。

### 2.4 雨情阈值

```c
/* common.h */
#define RAIN_ADC_THRESHOLD_SMALL  (2500)  /* > 此值：无雨 */
#define RAIN_ADC_THRESHOLD_MIDDLE (2000)  /* <= 此值：中雨 */
#define RAIN_ADC_THRESHOLD_BIG    (1500)  /* <= 此值：大雨 */
```

**判定逻辑**（`raindrop.c`）：

```c
if (adcRaw > 2500)      return RAIN_NONE;    /* 无雨 */
else if (adcRaw > 2000) return RAIN_SMALL;   /* 小雨 */
else if (adcRaw > 1500) return RAIN_MIDDLE;  /* 中雨 */
return RAIN_BIG;                             /* 大雨 */
```

**实测**：干燥时 ADC 2895~3500，滴水后明显下降。

**调优**：见 [§6](#6-雨情阈值标定)。

### 2.5 LoRa 参数

```c
/* lora_as32.h */
#define LORA_DEFAULT_CHAN      (0x3D)   /* 471MHz */
#define LORA_AIR_SPEED_2K4     (0x02)   /* 2.4kbps */
#define LORA_UART_BAUD_9600    (0x03 << 3)
#define LORA_UART_8N1          (0x00)
#define LORA_OPTION_TRANSPARENT (0x40)
```

**⚠️ 两机必须完全一致**，否则收不到。

| 参数 | 可选值 | 说明 |
|---|---|---|
| 信道 | 0x00 ~ 0xFF | 0x3D = 471MHz（-C 版出厂） |
| 空中速率 | 0x02(2.4k) / 0x04(9.6k) / 0x05(19.2k) | 越快距离越近 |
| 串口波特率 | 0x03(9600) / 0x07(115200) | 必须与 MCU 一致 |
| 模式 | 0x40(透明) / 0xC0(定点) | 本工程用透明 |

## 3 主机参数详解

### 3.1 水位报警阈值 `WATER_ALARM_THRESHOLD`

```c
/* master_app.h */
#define WATER_ALARM_THRESHOLD  (70)   /* 70% */
```

**判定**（`master_app.c`）：

```c
if (master_data.waterValid && (master_data.waterLevel > WATER_ALARM_THRESHOLD))
    master_data.waterAlarm = 1;
else
    master_data.waterAlarm = 0;
```

> **注意是严格大于**：70 不报警，71 才报警。
> 若想让 70 也报警，改成 69。

**报警时**：
- 蜂鸣器立即响（每 500ms 翻转）
- OLED 第 3 行加 `!`（`水位:75%!`）
- OLED 第 4 行显示 `水位过高`（覆盖雨情显示）
- **不遵循** 10 秒刷新周期，跳变瞬间立即刷屏

### 3.2 屏幕刷新周期 `OLED_REFRESH_MS`

```c
/* master_app.h */
#define OLED_REFRESH_MS        (10000)   /* 10 秒 */
```

**作用**：OLED 渲染间隔。数据每秒更新，但屏幕按此周期渲染。

**为什么不解耦成 1 秒**：OLED 通过软件 I2C 刷新一屏（1024 字节）需要几十毫秒，
每秒刷一次会明显闪烁，且占用主循环。

| 值 | 效果 |
|---|---|
| 10000（当前） | 10 秒刷新，数据实时更新 |
| 5000 | 5 秒刷新，更及时但略闪 |
| 1000 | 1 秒刷新，明显闪烁（不推荐） |
| 30000 | 30 秒刷新，很稳但响应慢 |

> **报警不受此参数影响** —— 报警跳变时立即刷屏。

### 3.3 断线超时 `RX_TIMEOUT_MS`

```c
/* main.c */
#define RX_TIMEOUT_MS (5000)   /* 5 秒 */
```

**作用**：超过此时间没收到数据 → 显示"等待从机" + 清报警 + 关蜂鸣器。

**取值依据**：从机 1 秒一帧，留 5 倍余量。

| 值 | 效果 |
|---|---|
| 5000（当前） | 5 秒没数据判定断线 |
| 2000 | 更灵敏，但网络抖动可能误判 |
| 10000 | 更宽容，但断线后要等 10 秒才提示 |

> **必须清理报警**：否则断线前正在报警的话，蜂鸣器会无限长响。

### 3.4 串口发送缓冲 `TX_LINE_MAX` / `USART1_TX_LIMIT`

```c
/* main.c */
#define TX_LINE_MAX       (240)
#define USART1_TX_LIMIT   (256)
```

**背景**：`USART1_SendBuffer()` 只有一个 DMA 发送缓冲，
超长数据会被**静默截断**（`if (len > USART1_TX_BUFFER_SIZE) len = USART1_TX_BUFFER_SIZE;`）。

**约束**：`[RX] ` (5) + 帧长 + `\r\n` (2) ≤ 256

```
正常：5 + 71 + 2 = 78 B     ✅
最坏：5 + 256 + 2 = 263 B   ❌ 会被截断
```

所以代码做双重检查：

```c
if (((u32)k + frameLen + 2u <= TX_LINE_MAX) &&
    ((u32)k + frameLen + 2u <= USART1_TX_LIMIT))
{
    /* 才发送 */
}
```

### 3.5 字库开关 `OLED_USE_FONT`

```c
/* oled_font.h */
#define OLED_USE_FONT   1   /* 必须是 1 */
```

**作用**：是否编译 GB2312 汉字字库。

| 值 | Flash 占用（RO-data） | 汉字显示 |
|---|---|---|
| 1（当前） | 122206 B | ✅ 正常 |
| 0 | 498 B | ❌ 显示方块/空白 |

**影响**：设为 1 后 Flash 增加约 120KB。
STM32F103ZE 有 512KB Flash，够用。

## 4 常见调优场景

### 4.1 想让报警更早触发

```c
/* code/master/user/api/master_app.h */
#define WATER_ALARM_THRESHOLD  (60)   /* 70 -> 60 */
```

重新编译主机、烧录。

### 4.2 想让屏幕刷新更快

```c
/* code/master/user/api/master_app.h */
#define OLED_REFRESH_MS        (5000)   /* 10 秒 -> 5 秒 */
```

### 4.3 想改报警蜂鸣节奏

```c
/* code/master/user/main.c，搜 500 */
if (beepMs >= 500)   /* 改小响得更急，改大响得更慢 */
{
    beepMs = 0;
    beepOn = (u8)(!beepOn);
    Beep_Ctrl(beepOn);
}
```

| 值 | 效果 |
|---|---|
| 200 | 急促"嘀嘀嘀" |
| 500（当前） | "哔—哔—" |
| 1000 | 慢速"哔——哔——" |

### 4.4 想让从机省电（降低上报频率）

```c
/* code/slave/user/api/sensor_report.h */
#define REPORT_INTERVAL_MS (5000)   /* 1 秒 -> 5 秒 */
```

> 注意：主机刷新周期是独立的 10 秒，从机改慢不影响显示频率。

### 4.5 想消除串口的 ADC 打印（太吵）

```c
/* code/slave/user/api/sensor_report.c，Report_PrintCN() */
n += Report_Append(&line[n], "%");
/* 删掉下面这几行 */
n += Report_Append(&line[n], "(ADC=");
n += Report_UInt(&line[n], pData->level.adc);
n += Report_Append(&line[n], ")");
```

### 4.6 想提高 LoRa 空中速率（缩短发送时间）

```c
/* 两机的 main.c 都要改，必须一致 */
config.speed = LORA_UART_8N1 | LORA_UART_BAUD_9600 | LORA_AIR_SPEED_9K6;
```

| 速率 | 宏 | 发送 71B 耗时 | 距离 |
|---|---|---|---|
| 2.4k（当前） | `LORA_AIR_SPEED_2K4` | ~74ms（串口限制） | 最远 |
| 9.6k | `LORA_AIR_SPEED_9K6` | 受串口 9600 限制 | 较近 |
| 19.2k | `LORA_AIR_SPEED_19K2` | 受串口 9600 限制 | 更近 |

> **注意**：串口 9600 是瓶颈（74ms），提高空中速率对总耗时帮助有限。
> 要真正提速需同时提高串口波特率（`LORA_BRR` 和模块配置）。

## 5 水位门限标定

### 5.1 什么时候需要标定

出现以下情况说明门限表与实际传感器不匹配：

| 现象 | 说明 |
|---|---|
| 满水只显示 60~80% | 门限表的高端阈值太大 |
| 空水就显示 10~20% | 噪声或门限表低端太小 |
| 变化不线性 | 门限表与实际曲线不符 |

### 5.2 标定步骤

**Step 1：采集实测数据**

看从机串口输出的 `(ADC=xxx)`：

```
空水（探头完全干燥）：ADC ≈ 20
半水（水面在中间）：  ADC ≈ ?
满水（水面到顶）：    ADC ≈ 716
```

**Step 2：记录两个端点**

| 状态 | ADC | 目标百分比 |
|---|---|---|
| 空水 | 20 | 0% |
| 满水 | 716 | 100% |

**Step 3：按比例重算门限表**

如果传感器**线性**（多数情况近似线性）：

```
门限(p%) = 空水ADC + (满水ADC - 空水ADC) × p / 100
```

以空水 20、满水 716 为例：

| 百分比 | 计算 | 新门限 | 旧门限 |
|---|---|---|---|
| 100% | 20 + 696×1.00 = 716 | **716** | 1100 |
| 90% | 20 + 696×0.90 = 646 | **646** | 900 |
| 80% | 20 + 696×0.80 = 577 | **577** | 600 |
| 70% | 20 + 696×0.70 = 507 | **507** | 440 |
| 60% | 20 + 696×0.60 = 438 | **438** | 340 |
| 50% | 20 + 696×0.50 = 368 | **368** | 300 |
| 40% | 20 + 696×0.40 = 298 | **298** | 250 |
| 30% | 20 + 696×0.30 = 229 | **229** | 220 |
| 20% | 20 + 696×0.20 = 159 | **159** | 190 |
| 10% | 20 + 696×0.10 = 90 | **90** | 160 |

**Step 4：改 `level.c`**

```c
/* code/slave/user/api/level.c */
static const u16 level_threshold[LEVEL_SEGMENT_COUNT] =
{
    716,    /* ADC >= 716  ==> 100% */
    646,    /* ADC >= 646  ==>  90% */
    577,    /* ADC >= 577  ==>  80% */
    507,    /* ADC >= 507  ==>  70% */
    438,    /* ADC >= 438  ==>  60% */
    368,    /* ADC >= 368  ==>  50% */
    298,    /* ADC >= 298  ==>  40% */
    229,    /* ADC >= 229  ==>  30% */
    159,    /* ADC >= 159  ==>  20% */
     90,    /* ADC >=  90  ==>  10% */
};
```

> **数组必须从大到小排列**，因为判定是从高往低逐段比对。

**Step 5：验证**

重新编译烧录，看串口输出：
- 空水 → `水位:0%`
- 满水 → `水位:100%`

### 5.3 非线性传感器

如果传感器输出与液位**明显非线性**（XPT2046 就是），
不能用上面的线性公式，要**逐点实测**：

| 步骤 | 操作 |
|---|---|
| 1 | 空水，记录 ADC₀ |
| 2 | 加水到 10%，记录 ADC₁₀ |
| 3 | 加水到 20%，记录 ADC₂₀ |
| ... | ... |
| 11 | 满水，记录 ADC₁₀₀ |
| 12 | 把 ADC₁₀₀ ~ ADC₁₀ 依次填入 `level_threshold[]` |

### 5.4 死区调整

标定后如果**空水仍报 10%**，说明死区不够：

```c
/* level.h */
#define LEVEL_IGNORE_BELOW_MM (18)   /* 9 -> 18，忽略到 20% 档 */
```

## 6 雨情阈值标定

### 6.1 采集实测数据

看从机串口输出：

```
干燥：  温度:26.4℃,...,无雨,...    ← ADC 应该在 2900~3500
滴水后：温度:26.4℃,...,小雨,...    ← ADC 下降
```

如果需要看 ADC，可临时在 `Report_PrintCN()` 里加雨滴 ADC 打印。

### 6.2 调整阈值

```c
/* code/slave/user/api/common.h */
#define RAIN_ADC_THRESHOLD_SMALL  (2500)   /* 无雨/小雨分界 */
#define RAIN_ADC_THRESHOLD_MIDDLE (2000)   /* 小雨/中雨分界 */
#define RAIN_ADC_THRESHOLD_BIG    (1500)   /* 中雨/大雨分界 */
```

| 现象 | 调整 |
|---|---|
| 干燥就报小雨 | 调大 `SMALL`（如 2800） |
| 大雨了还报小雨 | 调小 `MIDDLE` / `BIG` |
| 太灵敏 | 三个阈值都调大 |
| 太迟钝 | 三个阈值都调小 |

### 6.3 判定表（当前值）

| ADC | 雨情 |
|---|---|
| > 2500 | 无雨 |
| 2001 ~ 2500 | 小雨 |
| 1501 ~ 2000 | 中雨 |
| ≤ 1500 | 大雨 |

## 7 参数修改注意事项

### 7.1 ⚠️ 编码陷阱

**所有 `.c` / `.h` 的编码不统一**：

| 文件 | 编码 |
|---|---|
| `sensor_report.c` / `sensor_report.h` | GBK |
| `level.c` / `level.h` | **UTF-8 与 GBK 混合** |
| 其他多数文件 | GBK |
| `master_app.c` / `master_app.h` | GBK（含汉字字面量，必须 GBK） |

**改参数时的安全做法**：

1. **只改纯 ASCII 的代码行**（宏定义、数字）
2. **不要动中文注释**
3. 用支持 GBK 的编辑器，或用 Python 按字节改

> `master_app.c` 里有 `OLED_ShowString(0, 6, "水位过高")` 这样的 GBK 字面量，
> 如果用 UTF-8 保存，OLED 会显示乱码。

### 7.2 ⚠️ 改完必须重新编译烧录

参数在源码里，改完必须：

1. Keil 重新编译（F7）
2. 烧录对应板子（F8）
3. 如果是 **LoRa 参数**，**两块板子都要改、都要烧**

### 7.3 ⚠️ LoRa 参数必须双端一致

| 参数 | 必须一致 |
|---|---|
| 地址 | ✅ |
| 信道 | ✅ |
| 空中速率 | ✅ |
| 串口波特率 | ✅ |
| 传输模式 | ✅ |

任何一项不一致 → 收不到数据。

### 7.4 ⚠️ 不要把上报周期设太短

`REPORT_INTERVAL_MS < 500` 会导致：
- DHT20 来不及测量，温湿度开始出错
- LoRa 模块持续发射，供电压力大
- 主循环来不及处理其他任务

### 7.5 ⚠️ 不要把屏幕刷新设太短

`OLED_REFRESH_MS < 2000` 会导致：
- OLED 明显闪烁
- 软件 I2C 占用大量 CPU 时间
- 可能影响串口收帧（虽然用了中断缓冲，但主循环变慢）
