## 1 工具链

| 项 | 版本 | 说明 |
|---|---|---|
| IDE | Keil MDK-ARM | **V5.24.2**（本工程验证版本） |
| 编译器 | ARMCC | **V5.06 update 5** (build 528) |
| 器件包 | Keil.STM32F1xx_DFP | **2.2.0** |
| 目标芯片 | STM32F103ZE | 512KB Flash / 64KB RAM |
| 调试器 | ST-Link | 板载或外接 |

### 1.1 为什么用 ARMCC V5 而不是 V6

| 项 | ARMCC V5 (AC5) | ARMCC V6 (AC6, 基于 Clang) |
|---|---|---|
| 兼容性 | 老工程直接编译 | 部分语法/内联汇编需改 |
| 本工程 | ✅ 已验证 0 Error | 未验证 |

本工程用标准外设库（SPL），是老式 C 代码风格，
**建议用 ARMCC V5**，避免 V6 的严格检查带来额外工作量。

### 1.2 安装器件包

如果打开工程提示找不到 `STM32F103ZE`：

1. Keil → **Pack Installer**
2. 搜索 `STM32F1`
3. 安装 **Keil.STM32F1xx_DFP 2.2.0**
4. 重启 Keil

## 2 Keil MDK 配置

### 2.1 工程文件位置

```
code/slave/project/STM32F103ZET6_Project.uvprojx    ← 从机工程
code/master/project/STM32F103ZET6_Project.uvprojx   ← 主机工程
```

双击 `.uvprojx` 打开。

### 2.2 关键配置项

| 编译器 | Options → Target | ARMCC V5.06 |
| 输出目录 | Options → Output | `Objects\` |
| 生成 HEX | Options → Output → Create HEX File | ✅ 勾选 |
| 头文件路径 | Options → C/C++ → Include Paths | 见下 |

### 2.3 头文件路径

必须包含（从机/主机相同）：

```
..\libraries\CMSIS
..\libraries\CMSIS\CM3\DeviceSupport\ST\STM32F10x
..\libraries\STM32F10x_StdPeriph_Driver\inc
..\user
..\user\api
```

> 路径配置在 `.uvprojx` 里，已随工程提交，一般不用手动改。

### 2.4 源文件注册

**从机**：40 个文件
**主机**：43 个文件（多 `oled.c` / `master_app.c` / `frame_assembler.c`）

新增 `.c` 文件时，必须在 Keil 里**右键分组 → Add Existing Files** 加入工程，
否则不会参与编译，链接时会报 `Undefined symbol`。

> **典型坑**：`master_app.c` 注册了但 XML 位置插错（插进了库分组），
> 导致文件不参与编译，链接报 4 个 `Undefined symbol`。
> 验证方法：编译日志里应该能看到 `compiling master_app.c...`

## 4 编译与烧录

### 4.1 Keil 图形界面

| 操作 | 快捷键 |
|---|---|
| 编译（增量） | **F7** |
| 重新编译（全量） | 工具栏 Rebuild |
| 烧录 | **F8** |
| 进入调试 | Ctrl+F5 |

### 4.2 命令行编译

```powershell
# 从机
& 'C:\Keil_v5\UV4\UV4.exe' -b 'code\slave\project\STM32F103ZET6_Project.uvprojx' -j0 -o build_slave.log

# 主机
& 'C:\Keil_v5\UV4\UV4.exe' -b 'code\master\project\STM32F103ZET6_Project.uvprojx' -j0 -o build_master.log
```

**返回码**：

| 码 | 含义 |
|---|---|
| 0 | 无警告无错误 |
| 1 | 有警告 |
| 2+ | 有错误 |

> `-j0` 表示不显示进度对话框，`-o` 指定日志文件。
> 注意：`-b` 是增量编译，要全量重编需先删除 `Objects/*.o`。

### 4.3 编译产物

| 文件 | 从机 | 主机 | 说明 |
|---|---|---|---|
| `.hex` | 35585 B | 373712 B | **烧录用** |
| `.axf` | 405220 B | 499528 B | 调试用（含符号） |

**主机的 HEX 大得多**，因为含 120KB 汉字字库。

### 4.4 验证编译结果

编译日志末尾应该看到：

```
Program Size: Code=12078 RO-data=498 RW-data=56 ZI-data=2664
".\Objects\STM32F103ZET6_Project.axf" - 0 Error(s), 3 Warning(s).
```

| 工程 | Code | RO-data | RW-data | ZI-data |
|---|---|---|---|---|
| 从机 | 12078 | 498 | 56 | 2664 |
| 主机 | 10610 | **122206** | 28 | 4492 |

> **3 个 Warning 是正常的**，都来自 `i2c.c`：
> ```
> warning: #61-D: integer operation result is out of range
> PIOB->CRL &= ~(0x0f << 28);
> ```
> `0x0F << 28` 超出 int 范围。这是标准库示例代码的遗留问题，不影响功能。
> 如果想让警告清零，改成 `~(0x0FUL << 28)`。

## 5 ⚠️ 编码陷阱（必读）

### 5.1 编码不统一

**这是本工程最容易毁文件的地方。**

| 文件 | 编码 | 备注 |
|---|---|---|
| `sensor_report.c` / `.h` | **GBK** | |
| `level.c` / `level.h` | **UTF-8 与 GBK 混合** | ⚠️ 最危险 |
| `master_app.c` / `.h` | **GBK** | 含汉字字面量，必须 GBK |
| `oled.c` / `oled.h` | GBK | |
| 其他多数文件 | GBK | |

**验证方法**：

```python
b = open(path, 'rb').read()
try:
    b.decode('gbk');   print('GBK')
except:
    try: b.decode('utf-8'); print('UTF-8')
    except: print('混合编码')
```

### 5.2 为什么 `master_app.c` 必须是 GBK

代码里有汉字字面量：

```c
OLED_ShowString(0, 6, "水位过高");
OLED_ShowString(0, 0, "温度:");
```

`OLED_ShowString()` 内部按 **GBK 解码**汉字（`OLED_GbkDecode()`），
用 GBK 字节算字模索引：

```c
/* oled.c */
*idx = (u16)(hi - 0xB0) * 94 + (lo - 0xA1);
```

**如果用 UTF-8 保存**：
- UTF-8 的"温"是 3 字节 `E6 B8 A9`
- GBK 解码器会把它拆成两个非法字节
- 结果：**显示乱码或空白**

### 5.3 安全修改方法

#### 方法 A：只改 ASCII 区域（推荐）

```c
/* 只改这种行，不碰中文注释 */
#define WATER_ALARM_THRESHOLD  (70)   ← 只改数字
```

#### 方法 B：用 Python 按字节替换

```python
# 读原始字节
b = open(path, 'rb').read()

# 只替换纯 ASCII 的部分
old = b'#define WATER_ALARM_THRESHOLD  (70)'
new = b'#define WATER_ALARM_THRESHOLD  (60)'
assert b.count(old) == 1
b = b.replace(old, new)

# 写回（不经过解码/编码，中文一个字节不动）
open(path, 'wb').write(b)
```

#### 方法 C：整文件转码（谨慎）

如果确实要改中文注释：

```python
# 先解码为 Unicode
s = open(path, 'rb').read().decode('gbk')

# 修改
s = s.replace('旧注释', '新注释')

# 再编码回 GBK
open(path, 'wb').write(s.encode('gbk'))
```

> ⚠️ 对 `level.c` / `level.h`（混合编码）**不要用这个方法**，
> 因为 `.decode('gbk')` 会直接失败。

### 5.4 Keil 里的注意事项

> **⚠️ 如果 Keil 里打开着某个文件，改完代码后不要再保存那个文件**，
> 否则会用编辑器里的旧内容覆盖磁盘上的新版本。

正确流程：
1. 在外部工具改完文件
2. Keil 里执行 **File → Reload**（重新从磁盘加载）
3. 再编译

### 5.5 串口助手编码

从机串口输出中文（`温度:26.4℃,湿度:49.6%,无雨,水位:80%`）。

**串口助手必须选 GBK 编码**，否则中文乱码。

## 6 常见问题

### 6.1 编译报错 `cannot open source input file "xxx.h"`

**原因**：头文件路径没配 或 引用了不存在的文件。

**已知案例**：`oled.h` 里 `#include "usart.h"`（移植残留，本工程没有 `usart.h`）。
已修复（删除该行）。

### 6.2 编译报错 `identifier "OLED_ADDR" is undefined`

**原因**：宏定义缺失。

`OLED_ADDR` / `WRITE_FLAG` / `READ_FLAG` / `I2C_RETRY_COUNT` 原本在 `usart.h` 里，
随文件一起丢失了。已补进 `i2c.h`：

```c
#define OLED_ADDR        (0x3C)
#define WRITE_FLAG       (0x00)
#define READ_FLAG        (0x01)
#define I2C_RETRY_COUNT  (3)
```

### 6.3 链接报错 `Undefined symbol Master_Display`

**原因**：`master_app.c` 没有参与编译。

**检查**：
1. Keil 工程里是否注册了 `master_app.c`
2. 编译日志里有没有 `compiling master_app.c...`
3. `.uvprojx` 的 XML 结构是否正确（`<File>` 标签是否配对）

**验证 XML**：

```python
import xml.etree.ElementTree as ET
ET.parse('STM32F103ZET6_Project.uvprojx')   # 不报错说明合法
```

### 6.4 编译报错 `argument of type "u32 *" is incompatible with "u16 *"`

**原因**：`USART3_TakeFrame(u8 *dst, u16 *pLen)` 的第二个参数是 `u16*`。

```c
/* ❌ 错误 */
u32 rxLen = 0;
USART3_TakeFrame(s_rxBuf, &rxLen);

/* ✅ 正确 */
u16 rxLen = 0;
USART3_TakeFrame(s_rxBuf, &rxLen);
```

### 6.5 OLED 显示方块/乱码

**排查顺序**：

| 检查项 | 方法 |
|---|---|
| `OLED_USE_FONT` 是否为 1 | 看 `oled_font.h` |
| `.c` 文件是否为 GBK | 用 Python 验证编码 |
| I2C 是否有上拉 | 万用表测 PB6/PB7 静态电压（应接近 3.3V） |
| 地址是否正确 | `OLED_ADDR` 应为 `0x3C` |

### 6.6 屏幕一直显示"等待从机"

**说明完全没收到有效帧。**

| 检查项 | 说明 |
|---|---|
| 从机是否在发 | 看从机串口有没有每秒输出 |
| LoRa 参数是否一致 | 地址/信道/空中速率/波特率 |
| LoRa 接线是否接反 | 模块 TXD→PB11，RXD→PB10 |
| P5 跳线帽 | 必须选到无线模块 |
| 拼帧器是否生效 | 看主机串口 `[RX]` 是完整帧还是 32 字节碎片 |

### 6.7 屏幕显示 `温度:--` 但串口有数据

**根因**：收到的是 32 字节碎片，拼帧器没生效。

**检查**：
1. `frame_assembler.c` 是否注册进工程
2. `main.c` 里是否用了 `FrameAsm_Push()`
3. 主机串口 `[RX]` 行是否完整

## 7 调试技巧

### 7.1 串口打印是主要手段

两块板子的 USART1 都接 PC，**这是最重要的调试通道**。

| 板子 | 正常输出 |
|---|---|
| 从机 | `温度:26.4℃,湿度:49.6%,无雨,水位:80%(ADC=716)` |
| 主机 | `[RX] $RAIN,DHT20,T=26.5,...` |

**串口设置**：9600 8N1，**编码 GBK**。

### 7.2 LED 指示

`Led0_Toggle` 在关键路径上翻转，能直观看到程序在跑：

| 板子 | 翻转时机 |
|---|---|
| 从机 | 每上报一次 |
| 主机 | 每收到一帧有效数据 |

**LED 不闪 = 程序卡住或没进关键路径。**

### 7.3 蜂鸣器指示

主机的蜂鸣器在报警时翻转（每 500ms）。

如果蜂鸣器一直响不停 → 检查断线是否清了报警。

### 7.4 分段验证法

改完代码后，按这个顺序验证：

```
1. 编译 0 Error          → 语法正确
2. 烧录，看串口启动信息   → 程序在跑
3. 从机串口有数据输出     → 采集正常
4. 主机串口有 [RX] 完整帧 → LoRa 通 + 拼帧正常
5. OLED 显示正常数据      → 解析 + 渲染正常
6. 水位变化能触发报警     → 报警链路正常
```

**任何一步不通，问题就在那一步**，不要跳步排查。

### 7.5 用 Python 仿真验证逻辑

对于解析、拼帧、状态机这类纯逻辑，可以先用 Python 复刻验证，
比反复烧录快得多：

```python
# 复刻拼帧逻辑
class FrameAsm:
    def push(self, data):
        # ...
        pass

# 用真实碎片测试
frags = [full[0:32], full[32:64], full[64:]]
for f in frags:
    got, line = asm.push(f)
```

本项目的拼帧器和解析器都是先 Python 验证通过，再写 C 的。

### 7.6 检查 Flash/RAM 占用

编译日志的 `Program Size` 行：

```
Code=10610 RO-data=122206 RW-data=28 ZI-data=4492
```

| 项 | 含义 | 上限 |
|---|---|---|
| Code | 代码 | — |
| RO-data | 只读数据（字库在这里） | — |
| RW-data | 已初始化变量 | — |
| ZI-data | 未初始化变量 | — |
| **Flash** | Code + RO-data + RW-data | **512 KB** |
| **RAM** | RW-data + ZI-data | **64 KB** |

主机：Flash = 10610 + 122206 + 28 ≈ **130 KB**，RAM = 28 + 4492 ≈ **4.4 KB**。
都很宽裕。

## 8 项目约定

### 8.1 代码风格

| 项 | 约定 |
|---|---|
| 缩进 | 4 空格（`main.c` / `master_app.c`）或 Tab（部分旧文件） |
| 大括号 | 独占一行 |
| 类型 | 用 `u8` / `u16` / `u32`（`common.h` 定义）或 `uint8_t` 等 |
| 注释 | 中文，说明**为什么**而不只是**做什么** |

### 8.2 注释规范

关键决策点必须有注释说明原因：

```c
/*
 * 【关键】解析成功只更新缓存，不立即刷屏！
 * 数据实时到位（master_data 随时是最新值），
 * 但屏幕刷新由下面的 10 秒定时器统一驱动，
 * 这样避免每秒刷一次 OLED 导致闪烁。
 */
```

`【重点】` / `【修复】` / `【注意】` 等标记用于快速定位关键代码。

### 8.3 栈使用

**栈只有 1KB**（`startup_stm32f10x_hd.s` 里 `Stack_Size = 0x400`）。

**规则**：大于 64 字节的缓冲区放**静态区**（`.bss`），不放栈上。

```c
/* ✅ 正确 */
static u8 s_rxBuf[USART3_BUFFER_SIZE];      /* .bss */
static FrameAssembler_t s_frameAsm;         /* .bss，含 256B 缓冲 */
static u8 s_txLine[240];                    /* .bss */

/* ❌ 危险 */
void foo(void) {
    u8 buf[256];    /* 栈上 256B，叠加 DHT20 深调用可能溢出 */
}
```

### 8.4 中断安全

共享数据用「关中断 → 拷贝 → 清空 → 开中断」：

```c
static __inline u8 USART3_TakeFrame(u8 *dst, u16 *pLen)
{
    u8 got = 0;
    __disable_irq();
    if (usart3_value.flag) {
        *pLen = usart3_value.count;
        memcpy(dst, usart3_value.data, usart3_value.count);
        memset(&usart3_value, 0, sizeof(USART3_Data));
        got = 1;
    }
    __enable_irq();
    return got;
}
```

**不要改回**「先判断 flag 再 memset」的写法 —— 主循环在 `USART1_SendBuffer()` 里
会阻塞几十毫秒，这期间中断可能已经收完新帧，主循环再 memset 就把新帧清掉了。
