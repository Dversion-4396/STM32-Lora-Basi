## 2 Keil MDK 配置

### 2.1 打开工程

```
code/project/STM32F103ZET6_Project.uvprojx
```

> 工程内所有源文件均以 `..\libraries\`、`..\RT_Thread\` 等**相对路径**引用，
> 因此整个 `code/` 目录可任意移动位置，工程仍能正常打开。

### 2.2 目标芯片

| 参数 | 值 |
|---|---|
| Device | STM32F103ZE |
| Vendor | STMicroelectronics |
| CPU | Cortex-M3 |
| IROM | 0x08000000，512 KB |
| IRAM | 0x20000000，64 KB |
| 时钟 | 12 MHz（HSE 晶振频率，用于 Flash 算法） |

### 2.3 编译选项

| 选项 | 建议值 |
|---|---|
| Optimization | `-O0`（调试） / `-O2`（发布） |
| C99 Mode | 建议开启 |
| One ELF Section per Function | 开启（便于裁剪） |
| Browse Information | 调试时开启 |
| Warning Level | 至少 Level 2 |

### 2.4 调试器配置

| 参数 | 值 |
|---|---|
| Debugger | ST-Link Debugger |
| Port | **SW**（不是 JTAG） |
| Reset | Connect under Reset（芯片锁死时） |
| Flash Download | 勾选 Reset and Run |

> **为什么用 SWD 而不是 JTAG**：SWD 只需 2 根线（SWDIO + SWCLK），省引脚。
> 且本板 PA15/PB3/PB4 被 JTAG 占用，用 SWD 可以让这 3 个脚释放为普通 IO（需先禁 JTAG）。

## 3 目录结构说明

```
code/
├── user/                    ★ 应用层：唯一需要改的目录
│   ├── main.c               主程序入口
│   ├── stm32f10x_conf.h     标准库模块裁剪配置
│   ├── stm32f10x_it.c/h     中断服务函数
│   └── api/                 自写外设驱动封装
├── libraries/               ST 官方标准外设库
│   ├── CMSIS/
│   │   ├── CM3/             内核定义
│   │   └── startup/         启动汇编（向量表在这）
│   └── STM32F10x_StdPeriph_Driver/
│       ├── inc/
│       └── src/
├── RT_Thread/               RT-Thread Nano
│   ├── inc/                 内核头文件
│   ├── src/                 内核源码
│   └── port/                移植层（board.c / context_rvds.S / rtconfig.h）
└── project/                 Keil 工程文件
    ├── STM32F103ZET6_Project.uvprojx   工程主文件
    └── STM32F103ZET6_Project.uvoptx    调试配置
```

### 3.1 为什么要分层

| 目录 | 改动频率 | 说明 |
|---|---|---|
| `user/` | **高** | 业务逻辑，每次开发都改这里 |
| `libraries/` | 极低 | ST 官方代码，**不要改** |
| `RT_Thread/` | 极低 | RT-Thread 内核，只在移植时改 `port/` |
| `project/` | 低 | 增删源文件时改工程配置 |

> **原则**：只改 `user/`。这样库升级时可以直接替换 `libraries/` 而不影响业务代码。

## 4 编译与烧录

### 4.1 Keil GUI 编译

1. 打开工程
2. `Project → Build Target`（或 F7）
3. 查看 Build Output 窗口，确认 `0 Error(s)`

### 4.2 命令行编译

```bash
# 用 Keil 的 UV4.exe 命令行编译
UV4.exe -b "code\project\STM32F103ZET6_Project.uvprojx" -j0 -o "build.log"

# 返回码：0=无警告，1=有警告，2+=有错误
```

> **注意**：必须用 `Start-Process -Wait` 或在批处理中等待，
> 直接调用会在编译完成前返回（踩过这个坑）。

### 4.3 烧录

| 方式 | 工具 | 说明 |
|---|---|---|
| Keil 内烧录 | `Flash → Download`（F8） | 最常用 |
| ST-Link Utility | STM32 ST-LINK Utility | 批量烧录 |
| STM32CubeProgrammer | ST 官方 | 支持更多芯片 |
| 命令行 | `ST-LINK_CLI.exe` | 自动化产测 |

### 4.4 串口验证

| 参数 | 值 |
|---|---|
| 串口 | USART1（板载 CH340） |
| 波特率 | 9600 |
| 数据位 | 8 |
| 校验 | 无 |
| 停止位 | 1 |

**验证方法**：烧录后打开串口助手，应能看到程序输出。若无输出，按下面排查。

## 5 VS Code 辅助配置

`code/.vscode/` 下已包含三个配置文件：

| 文件 | 用途 |
|---|---|
| `c_cpp_properties.json` | 头文件路径、宏定义（代码提示用） |
| `launch.json` | 调试配置 |
| `settings.json` | 编辑器设置（编码、缩进等） |

### 5.1 c_cpp_properties.json 关键配置

```json
{
    "configurations": [{
        "name": "STM32",
        "includePath": [
            "${workspaceFolder}/user",
            "${workspaceFolder}/user/api",
            "${workspaceFolder}/libraries/CMSIS/CM3",
            "${workspaceFolder}/libraries/STM32F10x_StdPeriph_Driver/inc",
            "${workspaceFolder}/RT_Thread/inc",
            "${workspaceFolder}/RT_Thread/port"
        ],
        "defines": [
            "STM32F10X_HD",
            "USE_STDPERIPH_DRIVER"
        ],
        "intelliSenseMode": "gcc-arm",
        "cStandard": "c99"
    }]
}
```

> **两个必须的宏**：
> - `STM32F10X_HD` —— 声明高密度型号（512 KB Flash），否则寄存器定义不全
> - `USE_STDPERIPH_DRIVER` —— 启用标准外设库

## 6 常见问题

### 6.1 编译类

| 问题 | 原因 | 解决 |
|---|---|---|
| `L6200E: Symbol xxx multiply defined` | 强符号重复定义 | 工程层排除重复的 .c 文件 |
| `L6002U: Could not open file xxx.o` | 引用了不存在的源文件 | 检查工程文件列表，移除失效项 |
| `cannot open source input file "xxx.h"` | 头文件路径未配置 | 在 C/C++ → Include Paths 添加 |
| 大量 `#1-D: last line of file ends without a newline` | 文件末尾缺换行 | 无害，可忽略；或批量修复 |

### 6.2 烧录类

| 问题 | 原因 | 解决 |
|---|---|---|
| `No target connected` | 芯片未识别 | 检查 SWD 接线、供电 |
| `Cannot Load Flash Programming Algorithm` | 缺 Flash 算法 | 补对应 `*Loader.bin` |
| `Error: Flash Download failed - Target DLL has been cancelled` | 芯片锁死 / 读保护 | Connect under Reset；或解除读保护 |
| 烧录成功但不运行 | 复位方式不对 | 勾选 Reset and Run |

### 6.3 运行类

| 问题 | 原因 | 解决 |
|---|---|---|
| **串口无输出** | **中断函数名大小写错误** | 见下方专门说明 |
| 程序卡死 | HardFault / 死循环 | 用调试器看 PC 与 LR |
| LED 不亮 | 低电平点亮被搞反 | 本板 DS0/DS1 都是**低电平点亮** |
| 串口乱码 | 波特率或时钟配置错误 | 算 BRR；核对 HSE_VALUE |

### 6.4 ★ 中断函数名大小写（最容易踩的坑）

启动文件 `startup_stm32f10x_hd.s` 里定义了弱符号：

```asm
DCD     USART3_IRQHandler          ; 向量表：硬件只认这个名字
EXPORT  USART3_IRQHandler [WEAK]   ; 弱符号，允许被顶替
USART3_IRQHandler                  ; 默认实现
        B       .                   ; 空壳：原地死循环
```

若 C 代码里写成 `Usart3_IRQHandler`（小写 s）：
- **编译不报错**
- **链接不报错**（弱符号允许顶替，但名字对不上就没人顶替）
- **向量表仍指向空壳 `B .`** → 一进中断 CPU 原地死循环

**症状**：串口一个字节都没发出去，灯不亮，看起来像"卡在某处"。

**修法**：函数名必须与启动文件**完全一致**（含大小写）—— `USART3_IRQHandler`。

> 这类 bug 极难定位，因为编译链接全绿。**建议写完后用 `fromelf` 查符号表确认**：
> ```
> fromelf --text -s Objects\xxx.axf -o sym.txt
> ```
> 查 `USART3_IRQHandler` 的类型，必须是 `Gb`（全局代码），不能是 `Wk`（弱符号）。

### 6.5 Keil 增量编译的坑

**Keil 增量编译只看时间戳**。如果文件内容变了但 mtime 没变（例如用脚本还原文件），下次编译会复用旧 `.o`，导致"代码改对了、固件还是坏的"。

**对策**：改任何被编译的文件后，**删 `project/Objects` 全量重编**。

### 6.6 Keil 打开时会覆盖磁盘修改

**Keil 开着时，IDE 内存里的旧文件会把你写到磁盘的修改覆盖回去**。

**对策**：改文件前先让 Keil 保存并关闭。

## 7 调试技巧

### 7.1 HardFault 定位

1. 在 `HardFault_Handler` 设断点
2. 触发后查看调用栈（Call Stack）
3. 若栈已损坏，查看 `LR`（链接寄存器）判断是从线程还是中断进入
4. 查看 `SCB->CFSR`、`SCB->HFSR` 判断故障类型
5. 用反汇编窗口定位出错指令

### 7.2 逻辑分析仪

| 场景 | 接哪几根线 | 看什么 |
|---|---|---|
| SPI Flash 通信 | CS / SCK / MOSI / MISO | 指令码、时序、CPOL/CPHA |
| I2C EEPROM | SCL / SDA | 地址、ACK、时序 |
| RS485 | A / B（或 DE + TX） | 方向切换时机、帧边界 |
| LoRa SPI | NSS / SCK / MOSI / BUSY | 寄存器读写是否正确 |

### 7.3 串口打印调试

**前提**：必须重定向 `printf` 到串口。

```c
#include <stdio.h>

int fputc(int ch, FILE *f)
{
    while (!(USART1->SR & USART_SR_TXE));
    USART1->DR = (uint8_t)ch;
    return ch;
}
```

> **注意**：RT-Thread 环境下也可以用 `rt_kprintf`，但需在 `rtconfig.h` 中配置 `RT_USING_CONSOLE` 并实现输出。

### 7.4 功耗测量

**不能用万用表直接串在电源上测**（采样率太低，抓不到脉冲）。

正确方法：

1. 高边串一个 1 Ω 精密电阻，用示波器测压降
2. 或用专用功耗分析仪（Nordic PPK2 / Joulescope）
3. 长时间统计用库仑计

## 8 项目约定

### 8.1 代码风格

| 项目 | 约定 |
|---|---|
| 缩进 | 4 空格 |
| 命名 | 函数 `Module_Function()`，变量小写下划线 |
| 注释 | 关键逻辑必须注释，魔数必须说明 |
| 文件编码 | UTF-8（无 BOM） |
| 换行 | CRLF（Windows） |

### 8.2 提交规范

```
<type>: <subject>

type:
  feat     新功能
  fix      修复 bug
  docs     文档
  refactor 重构
  test     测试
  chore    构建/工具
```

**示例**：

```
feat: 增加 SX1262 LoRa 驱动
fix: 修正 RS485 方向切换时序（等 TC 而非 TXE）
docs: 补充功耗模型计算依据
```

### 8.3 不要提交的东西

`.gitignore` 已排除：

- `project/Objects/`、`project/Listings/`（编译产物，35 MB）
- `*.uvguix.*`（各人窗口布局，因人而异）
- `__pycache__/`、`*.pyc`
- 系统文件（`Thumbs.db`、`.DS_Store`）
