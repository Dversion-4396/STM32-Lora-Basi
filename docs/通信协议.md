# 通信协议

> 私有帧格式、TDMA 时隙规划与可靠性设计

---

## 1 为什么用私有协议而不是 LoRaWAN

| 方案 | 优点 | 缺点 | 本方案取舍 |
|---|---|---|---|
| **LoRaWAN** | 标准化、生态成熟 | 帧结构固定开销大；需部署 NS 服务器；入网流程复杂 | ✗ 不采用 |
| **私有帧** | 载荷可完全自定义；无服务器依赖；小规模自建合规 | 需自己实现可靠性机制 | ★ **采用** |

**三条理由**：

1. 私有帧可完全自定义上报内容与压缩方式，避免 LoRaWAN 的固定帧结构开销
2. 无需额外部署 LoRaWAN 服务器与入网流程
3. 微功率法规下自建小规模网络完全合规

## 2 物理层参数

| 参数 | 值 | 说明 |
|---|---|---|
| 频段 | 470.0 ~ 510.0 MHz | 中国微功率频段 |
| 调制 | LoRa（啁啾扩频） | — |
| 带宽 BW | 125 kHz | 兼顾速率与灵敏度 |
| 编码率 CR | 4/5 | — |
| 前导码 | 8 符号 | — |
| 显式头 | 是 | 含长度与 CR 信息 |
| 发射功率 | **+17 dBm** | 法规降额（标称 +22 dBm） |
| 扩频因子 SF | SF9 ~ SF12 自适应 | 近距用 SF9，远距/遮挡升 SF12 |
| 同步字 | 私有（非 LoRaWAN 公有） | 避免收到他人网络报文 |

### 扩频因子选择策略

| 场景 | 推荐 SF | 空中时间（32 B） | 说明 |
|---|---|---|---|
| 近距（< 800 m，视距） | SF9 | 246 ms | 省电优先 |
| 中距（800 m ~ 1.5 km） | SF10 | 452 ms | 平衡 |
| 远距（1.5 ~ 2 km） | SF11 | 905 ms | 保通 |
| 遮挡/边缘（> 2 km 或林区） | SF12 | 1810 ms | 最后手段 |

> **原则**：在满足链路余量的前提下取**最小可用 SF**。SF 每升一档，空中时间约翻倍，功耗同步上升。

## 3 帧格式

### 3.1 上行数据帧（节点 → 网关）

| 偏移 | 字段 | 长度 | 说明 |
|---|---|---|---|
| 0 | 前导码 | 2 B | 固定 `0xAA 0x55` |
| 2 | 节点 ID | 2 B | 网络内唯一，1 ~ 65535 |
| 4 | 序号 | 2 B | 递增计数，防重放 |
| 6 | 命令字 | 1 B | `0x01`=数据上报 |
| 7 | 载荷长度 | 1 B | TLV 区字节数 |
| 8 | 载荷 | N B | TLV 结构 |
| 8+N | 传感器状态 | 1 B | 位图，标记故障 |
| 9+N | CRC16 | 2 B | 整帧校验（CCITT-FALSE） |

**整帧长度**：`11 + N` 字节

### 3.2 传感器状态位图

| Bit | 含义 |
|---|---|
| 0 | 10 cm 层含水率异常 |
| 1 | 20 cm 层含水率异常 |
| 2 | 40 cm 层含水率异常 |
| 3 | 60 cm 层含水率异常 |
| 4 | 温度异常 |
| 5 | 电导率异常 |
| 6 | 雨量计异常 |
| 7 | 电池欠压 |

> **为什么需要状态位图**：让网关能区分「数值为 0」与「传感器故障」。
>
> 举例：某层含水率读数为 0，可能是**真的极度干旱**（业务上要报警），也可能是**传感器断线**（业务上要派人维修）。这两种情况的处置完全不同，**混在一起会把故障当成极端干旱，造成误判**。这一点在业务上非常重要。

### 3.3 TLV 载荷定义

| TLV 类型 | 长度 | 内容 | 编码 |
|---|---|---|---|
| `0x01` | 2 B | 10 cm 层含水率 | 0.1% 分辨率，大端，单位 0.1% |
| `0x02` | 2 B | 20 cm 层含水率 | 同上 |
| `0x03` | 2 B | 40 cm 层含水率 | 同上 |
| `0x04` | 2 B | 60 cm 层含水率 | 同上 |
| `0x05` | 2 B | 土壤温度 | 0.1 ℃ 分辨率，有符号（补码） |
| `0x06` | 2 B | 电导率 | µS/cm，大端 |
| `0x07` | 2 B | 雨量累计 | 0.1 mm 分辨率 |
| `0x08` | 2 B | 电池电压 | mV，大端 |

**TLV 编码示例**（10 cm 层 25.3% 含水率）：

```
01 02 00 FD
│  │  └─┴─ 0x00FD = 253 → 25.3%
│  └────── 长度 2 字节
└───────── 类型 0x01
```

**TLV 的优势**：可扩展。后续增加水位或土壤 pH 传感器时，**无需改动帧头**，只需定义新的类型码，老网关忽略未知类型即可。

### 3.4 下行配置帧（网关 → 节点）

| 偏移 | 字段 | 长度 | 说明 |
|---|---|---|---|
| 0 | 前导码 | 2 B | `0xAA 0x55` |
| 2 | 节点 ID | 2 B | 目标节点，`0xFFFF` = 广播 |
| 4 | 序号 | 2 B | 递增 |
| 6 | 命令字 | 1 B | 见下表 |
| 7 | 载荷长度 | 1 B | — |
| 8 | 载荷 | N B | — |
| 8+N | CRC16 | 2 B | — |

**下行命令字**：

| 命令字 | 功能 | 载荷 |
|---|---|---|
| `0x81` | 设置上报周期 | 2 B，单位秒 |
| `0x82` | 设置扩频因子 | 1 B，SF9~SF12 |
| `0x83` | 请求立即上报 | 无 |
| `0x84` | 时间同步 | 4 B，Unix 时间戳 |
| `0x85` | 设置时隙号 | 1 B |
| `0x86` | 读取设备信息 | 无 |
| `0x87` | 重启设备 | 无 |

### 3.5 ACK 帧

| 字段 | 长度 | 说明 |
|---|---|---|
| 前导码 | 2 B | `0xAA 0x55` |
| 节点 ID | 2 B | 被确认的节点 |
| 序号 | 2 B | 对应上行帧的序号 |
| 命令字 | 1 B | `0x02` = ACK |
| 状态 | 1 B | `0x00`=成功，其他=错误码 |
| CRC16 | 2 B | — |

## 4 TDMA 时隙规划

### 4.1 为什么用 TDMA 而不是随机竞争

| 方案 | 冲突率 | 节点功耗 | 可预测性 |
|---|---|---|---|
| 随机竞争（ALOHA） | 节点增多后迅速上升 | 高（不知道何时能发，只能延长接收窗） | 差 |
| **TDMA** | 无冲突（时隙隔离） | 低（到点就发，发完就睡） | 好 |

**结论**：采用**网关信标同步 + TDMA 时隙分配**。

### 4.2 时隙结构（60 min 周期）

```
├─ 信标时隙 5 s ─┤├─ 节点时隙 × N ─┤├─ 下行窗 10 s ─┤├────── 空闲 ──────┤
   网关广播         每节点 3 s        参数下发         事件上报 / 省电
   同步+时隙表      按 ID 顺序
```

| 时隙 | 时长 | 用途 |
|---|---|---|
| 信标时隙 | 5 s | 网关广播同步时间与时隙表 |
| 节点数据时隙 × N | 每节点 3 s | 各节点按 ID 顺序上报 |
| 下行配置窗 | 10 s | 网关下发参数 |
| 空闲保护 | 余量 | 异常事件即时上报 |

**以 20 个节点为例**：

```
信标 5 s + 20 × 3 s + 下行 10 s = 75 s
轮内占用率 = 75 / 3600 = 2.1%
```

**以 50 个节点为例**：

```
信标 5 s + 50 × 3 s + 下行 10 s = 165 s
轮内占用率 = 165 / 3600 = 4.6%
```

### 4.3 低占空比的两个好处

1. **留下大量空闲时间给异常事件即时上报** —— 强降雨触发的加密上报可以随时插入
2. **网关可以在轮内插入下行配置窗口而不挤占数据时隙**

这是低占空比设计的直接体现，也符合微功率设备对占空比的约束精神。

### 4.4 时隙同步机制

- 网关在每个周期起点广播**信标帧**，含当前时间戳与时隙表
- 节点收到信标后校准本地 RTC
- 节点根据自己的 ID 计算时隙偏移：`offset = 5 + (node_id - 1) × 3`（秒）
- 若节点错过信标（如刚唤醒），**跳过本轮**，等下轮同步，避免乱发冲突

## 5 可靠性设计

### 5.1 防重放攻击

**机制**：序号字段递增，网关维护每个节点的最新序号。

```
收到帧 → 比对序号
  ├─ 序号 > 已记录值  → 接受，更新记录
  ├─ 序号 = 已记录值  → 丢弃（重复）
  └─ 序号 < 已记录值  → 丢弃（回退/重放）
```

**序号回绕处理**：2 字节序号最大 65535，按 60 min 周期约 4.5 年回绕一次。回绕时需特殊处理（如检测大幅跳变时重置记录）。

### 5.2 CRC 校验

- 算法：**CRC-16/CCITT-FALSE**（多项式 `0x1021`，初值 `0xFFFF`）
- 覆盖范围：从节点 ID 到载荷末尾
- 校验失败直接丢弃，不回复 ACK

### 5.3 ACK 与重传

```
节点发送 → 等待 ACK（超时 2 s）
  ├─ 收到 ACK(成功) → 结束
  ├─ 收到 ACK(错误) → 记录错误，下次重试
  └─ 超时 → 重试（最多 3 次）
        └─ 仍失败 → 写入本地缓存，下轮优先发送
```

> **注意**：重传会占用额外时隙。因此重传次数受限，且优先在下一轮的空闲时段发送，避免打乱 TDMA 节奏。

### 5.4 数据缓存与补传

| 层级 | 位置 | 容量 | 用途 |
|---|---|---|---|
| 节点缓存 | MCU 内部 Flash | 约 100 帧 | 发送失败暂存 |
| 网关缓存 | W25Q128（16 MB） | 约 50 万帧 | 断网续传 |

**网关续传流程**：

1. 每帧上报数据写入 W25Q128，带时间戳与序号
2. MQTT QoS1，收到 PUBACK 才标记已发送
3. 连续 3 次发送失败或心跳超时 → 进入缓存模式
4. 网络恢复后按时间顺序补传，**速率限制**避免拥塞
5. 环形缓冲，容量满时覆盖最旧数据并**记录丢弃计数**

## 6 数据完整性保障

| 异常 | 检测方式 | 处理 |
|---|---|---|
| 帧头错误 | 前导码比对 | 丢弃 |
| CRC 错误 | CRC16 校验 | 丢弃，不 ACK |
| 重放报文 | 序号比对 | 丢弃 |
| 载荷越界 | 范围校验（如含水率 > 100%） | 丢弃该 TLV，标记可疑 |
| 传感器故障 | 状态位图 | 上报时带故障标记，不参与业务计算 |
| 时间戳异常 | 与网关时间比对 | 以网关时间为准 |

### 7.3 SL 651 对接

若需对接水文监测平台，按 SL 651 规约封装。关键点：

- 报文需包含测站编码、观测时间、要素编码
- 要素编码按 SL 651 附录定义（土壤含水率、降水量等）
- 需实现登录、心跳、定时上报三类报文

> 具体要素编码与报文结构请查阅 SL 651 正文，本文档不替代标准。
