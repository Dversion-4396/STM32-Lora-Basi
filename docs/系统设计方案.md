## 1 项目概述与需求分析

### 1.1 设计背景

河流流域的土壤墒情是防汛抗旱、灌区调度与农业生产的共同基础数据。流域内墒情站点通常沿河道呈带状分布：岸坡农田、河滩地、阶地、支流汇入口各需代表性测点，测点之间相距数百米至数公里，且多位于**无市电、无光纤、手机信号覆盖不稳定的野外环境**。

这一空间形态决定了两件事：**通信必须自建，供电必须自给**。

传统人工取样（烘干称重法）精度最高，但无法给出连续时间序列；市售一体式墒情站多采用 4G 直连，在山区河谷常因信号弱而丢数。本方案以 GD32 系列 MCU + SX1262 LoRa 射频构建私有低功耗无线传感网，网关侧再以 4G/北斗回传，形成「节点—网关—平台」三级结构，兼顾低功耗长待机、非视距绕射能力与自主可控。

### 1.2 设计目标

| 指标 | 目标值 |
|---|---|
| 节点续航 | ≥ 3 年（60 min 上报周期，无日照补充条件下降额） |
| 单跳覆盖 | 2.0 km（开阔河滩可放宽至 3.0 km） |
| 墒情测量 | 4 层深度，体积含水率 ±3%（标定后） |
| 数据完整率 | ≥ 95%（含断网续传） |
| 工作温度 | -40 ~ +70 ℃ |
| 防护等级 | IP66 以上 |

### 1.3 关键约束与设计取舍

方案中有三个约束直接决定了整体架构，必须先说清楚：

**法规约束**：470 MHz 属微功率短距离设备频段。依据工业和信息化部公告 2019 年第 52 号，列入《微功率短距离无线电发射设备目录和技术要求》的设备无需频率使用许可与电台执照，但**不得擅自加大发射功率、不得额外加装射频功放、不得擅自更改天线**。因此模块标称 +22 dBm 的能力必须**降额到 +17 dBm 档使用**，链路预算按 +17 dBm 计算。

**能量约束**：节点无市电。LoRa 发射瞬时电流可达 100 mA 量级，而休眠电流仅 µA 级，二者**相差四个数量级**，因此**占空比（而非峰值功耗）决定续航**。模型显示 60 min 周期下平均电流 57 µA，理论续航以年计。

**传播约束**：节点天线受埋设条件限制只能架到 4 m 左右，属**低空链路**。低空无定向天线链路的地面反射会形成干涉衰落，因此**覆盖半径不能仅按自由空间公式外推**，必须叠加足够的衰落余量。

### 1.4 标准与规范依据

| 标准号 | 名称 |
|---|---|
| GB/T 20481 | 气象干旱等级 |
| SL 364 | 土壤墒情监测规范 |
| SL 651 | 水文监测数据通信规约 |
| SL/T 427 | 水资源监测数据传输规约 |
| 工信部公告 2019 年第 52 号 | 微功率短距离无线电发射设备目录和技术要求 |

> 上表标准号来自公开标准库检索结果，**具体条文阈值应在设计交底前逐条核对现行版本**，本文档不替代标准正文。

## 2 系统总体架构

### 2.1 三层拓扑

系统采用「感知层—汇聚层—应用层」三层结构，感知层与汇聚层之间为自建 LoRa 私有网，汇聚层与应用层之间走公网。

```
┌──────────────────────────────┐
│        应用层（云端/本地）      │
│  墒情数据库 · 旱情分析 · 预警  │
└──────────────▲───────────────┘
               │ MQTT / SL 651（公网）
┌──────────────┴───────────────┐
│   汇聚层：区域网关（常供电）    │
│  GD32F303 + SX1262 + 4G Cat.1 │
│  LoRa 接收 · 本地存储 · 补传   │
└───────▲──────────────▲────────┘
        │ LoRa 470MHz  │
┌─────────────┴───┐   ┌──────┴──────────┐
│  感知层 节点 #1  │   │  感知层 节点 #N  │
│ GD32L233+SX1262 │   │ GD32L233+SX1262 │
│ 4层墒情+雨量     │   │ 4层墒情+雨量     │
│ 太阳能+锂电      │   │ 太阳能+锂电      │
└─────────────────┘   └─────────────────┘
 （沿流域带状布设；丘陵超距时插入 LoRa 中继节点）
```

### 2.3 流域带状布点的拓扑选择

流域墒情测点沿河道纵向展开，横向范围小、纵向跨度大。据此比较三种组网方式：

| 拓扑 | 优点 | 缺点 | 适用性 |
|---|---|---|---|
| **星型** | 节点只发不收，功耗最低；结构简单，故障域小 | 依赖网关覆盖，超距需中继 | ★ **本方案主选** |
| Mesh | 自组织，可扩展覆盖 | 转发节点须长期开接收窗，功耗高一个量级 | 电池节点不适用 |
| 链型/中继 | 沿河道天然适配 | 逐跳延迟累积，单点故障影响下游 | 超距断面补充 |

**结论**：主拓扑取星型，网关架高（塔高 15 m）以争取视距；仅在个别超距断面插入**常供电中继**，避免让电池节点承担转发任务——因为转发要求节点长期开启接收窗，平均电流会从 µA 级跃升到 mA 级，续航从**年降到月**。

> 这是本方案与「通用 Mesh 宣传」最重要的取舍分歧。

## 3 主控芯片选型与设计

### 3.1 选型依据

系统对 MCU 的要求是：**极低休眠电流**（决定续航）、足够的外设（多路串口接传感器与射频、ADC 接电池电压监测）、工业级温度范围、国内供货与生态成熟。

据此确定**双芯片策略**：节点用低功耗系列，网关用高性能系列。

| 角色 | 型号 | 内核 | 主频 | Flash/RAM | 关键理由 |
|---|---|---|---|---|---|
| **节点** | GD32L233RCT6 | Cortex-M23 | 64 MHz | 256 KB / 32 KB | Stop < 2 µA、Standby < 0.4 µA；内置 Segment LCD 控制器；TRNG + CAU 硬件加密 |
| **网关** | GD32F303 | Cortex-M4 | 120 MHz | 更大 SRAM | 需同时跑 LoRa 驱动、4G AT 交互、文件系统与协议栈；21 通道 ADC；LQFP48/64/100/144 可选 |

**节点选 L233 的理由**：Stop 电流低于 2 µA、Standby 低于 0.4 µA 是续航的直接保障；Cortex-M23 内核在保证算力的同时静态功耗极低；内置 Segment LCD 控制器可直接驱动本地显示（现场调试与读数极为方便，且不占用 CPU）；TRNG + CAU 硬件加密单元可用于报文鉴权，防止伪造上报。

**网关选 F303 的理由**：需要同时跑 LoRa 驱动、4G 模组 AT 交互、本地文件系统与协议栈，120 MHz Cortex-M4 与更大 SRAM 更从容；21 通道 ADC 便于监测机柜温度、电池与各路电源。

### 3.2 节点 MCU 资源分配

| 资源 | 用途 |
|---|---|
| LPUART1 | 与 4 层墒情传感器 RS485 通信 |
| LPUART2 / USART | 调试串口、雨量计（可配脉冲输入） |
| SPI1 | SX1262 射频模块 |
| ADC_INx | 电池电压、太阳能板电压监测 |
| RTC | 定时唤醒（主唤醒源） |
| EXTI | 雨量计脉冲事件唤醒 |
| IWDG | 独立看门狗 |
| LCD | 现场读数显示 |

### 3.3 电源域与低功耗设计要点

- **分级供电**：MCU 常供电（Standby 域）；传感器、RS485 收发器、射频模块由 MOSFET 受控供电，非采样期完全断电，消除静态漏电。
- **未用 IO 处理**：未用管脚配置为模拟输入或推挽输出固定电平，避免浮空输入导致的漏电。
- **唤醒路径**：RTC 闹钟唤醒为常态；另保留一路外部中断（如雨量计脉冲）用于事件唤醒，使强降雨时段可自动加密上报。
- **Flash 与时钟**：采样任务完成后立即回 Standby；不必要时关闭不用的外设时钟与 PLL，以内部低速时钟维持 RTC。
- **看门狗**：独立看门狗在野外是必需项——死机自恢复的价值远高于漏掉一次采样。

## 4 土壤墒情传感器选型与标定

### 4.1 传感器参数要求

土壤墒情传感器是精度的源头。本方案选用**土壤温湿度电导率三合一变送器**，RS485/Modbus 输出，可长期埋入土壤。

| 参数 | 典型值 |
|---|---|
| 测量参数 | 体积含水率、温度、电导率 |
| 含水率量程 | 0 ~ 100 %（VWC） |
| 含水率精度 | ±3%（标定后） |
| 温度量程 | -40 ~ +80 ℃ |
| 供电 | **12 ~ 24 V DC** |
| 输出 | RS485 / Modbus RTU |
| 防护 | IP68（可长期埋设） |

> **供电电压 12~24 V 常被忽略**：节点若采用 3.7 V 锂电池，必须增加升压电路，而升压电路的效率与静态电流会直接吃掉续航。本方案的处理是**仅在采样时刻给传感器上电**，上电后等待稳定时间再读数，采样完成后立即断电。

### 4.2 测量原理与误差来源

主流土壤水分测量原理有两类：

| 原理 | 方法 | 精度 | 成本 | 适用 |
|---|---|---|---|---|
| **FDR**（频域反射） | 测介电常数推算含水率 | 中（标定后满足业务） | 低 | ★ **本方案选用** |
| TDR（时域反射） | 测电磁脉冲传播时间 | 高 | 显著更贵 | 科研级 |

选 FDR 类（电容/频域）的原因是成本与体积更适合大范围布点，且经过标定后可满足业务精度。

**主要误差来源**：

1. **土壤类型差异** —— 砂土、壤土、黏土的介电特性不同，出厂标定难以通用
2. **盐分影响** —— 电导率高时介电常数测量受干扰
3. **温度漂移** —— 需温度补偿
4. **埋设密实度** —— 传感器与土壤接触不良会形成气隙，读数偏低
5. **冻融** —— 结冰时含水率读数失真

### 4.3 标定方法与实施步骤

1. **取样**：在测点取原状土，测定干容重
2. **配比**：制备 5~7 个含水率梯度的土样（如 5%、10%、15%、20%、25%、30%、饱和）
3. **装填**：按现场密实度装入标定容器，插入传感器
4. **静置**：密封静置 24 h 使水分均匀
5. **读数**：每个梯度重复 3 次取均值
6. **拟合**：建立「传感器读数 → 体积含水率」的线性或多项式关系
7. **验证**：用烘干称重法（105 ℃，24 h）作为真值交叉验证

> 标定曲线应随土壤类型分区域管理，**不可跨土类套用**。

### 4.4 埋设深度与安装工艺

四层墒情典型埋设深度：**10 cm / 20 cm / 40 cm / 60 cm**。

- 对应不同根系活动层与水分运移层
- 开挖剖面后**分层回填、分层压实**，恢复原土层序
- 传感器与土壤**紧密接触**，避免留空隙
- 立杆垂直度偏差 < 2°
- 电缆穿管保护，接头做防水处理

## 5 LoRa 通信系统设计

### 5.1 射频器件选型

射频方案在 SX1262 与 SX1278 之间选择。二者都是 Semtech 的 LoRa 收发器，差异体现在灵敏度、接收电流与集成度上：

| 参数 | SX1262 | SX1278 | 取舍 |
|---|---|---|---|
| 频段 | 150~960 MHz | 137~525 MHz | 均覆盖 470 MHz |
| 最大功率 | +22 dBm | +20 dBm | 本方案降额至 +17 dBm |
| 接收电流 | **~4.6 mA** | ~10 mA | ★ SX1262 明显更优 |
| 灵敏度 | 优（SF12 约 -137 dBm） | 良 | SX1262 略优 |
| TCXO | 支持 | 通常需外置 | ★ 宽温稳定性更好 |

**选 SX1262 的决定性理由是接收电流**：虽然节点以发射为主，但下行配置、时间同步与 ACK 都需要开接收窗，接收电流低意味着可以放心地把接收窗开得更长，从而提升可靠性而不显著牺牲续航。此外 TCXO 在 -40~+70 ℃ 宽温范围内的频率稳定性，是野外设备可靠通信的前提。

### 5.2 链路预算与覆盖半径（量化）

覆盖半径不能只按自由空间公式估算，必须逐项累加所需余量。

**链路预算常数**：

| 项目 | 数值 |
|---|---|
| 发射功率 | +17 dBm（法规降额后） |
| 发射天线增益 | 2 dBi |
| 接收天线增益 | 3 dBi |
| 接收灵敏度（SF12, BW125） | -137 dBm |
| 频率 | 470 MHz |
| 电缆与接头损耗 | 1.5 dB |

**所需链路余量预算（逐项累加）**：

| 余量项 | 需求 |
|---|---|
| 阴影衰落（低空链路） | 8 dB |
| 雨衰与植被衰减 | 6 dB |
| 多径干涉衰落 | 6 dB |
| 器件老化与温漂 | 3 dB |
| 工程设计余量 | 10 dB |
| **合计** | **33 dB** |

**两个传播模型交叉验证**：

| 模型 | 路径损耗指数 n | 反解距离 | 剩余余量 |
|---|---|---|---|
| 自由空间（理想） | 2.0 | 约 24 km | 充裕 |
| 开阔河滩 | 2.7 | 约 3.0 km | 10 dB |
| 阶地灌木/作物季 | 3.2 | 约 1.0~1.5 km | 8 dB |
| 山地林区 | 3.8 | 约 0.8~1.0 km | 6 dB |

**结论**：取交集，**单跳覆盖半径设计值为 2.0 km**。
- 开阔河滩无遮挡（n=2.7）可放宽至 3.0 km
- 阶地灌木与作物季遮挡按 1.0~1.5 km 布点
- 山地林区按 0.8~1.0 km 布点

### 5.3 天线高度：工程自由度而非模型约束

有一个容易误判的点需要澄清。按第一菲涅尔区「0.6 余隙」判据，4 m 与 15 m 的天线组合在数百米外就会判定「地面遮挡」，从而得出链路不可用的结论——这与 LoRa 的实际工程表现明显矛盾。

**矛盾的原因是**：该判据面向**视距微波链路**，而此处是**低空、无定向天线、宽带扩频链路**，LoRa 的啁啾扩频本身对多径有很强的容忍度。

因此本方案**不用菲涅尔判据定半径，而是用「余量预算」定半径**，把天线高度当作降低衰落深度的工程手段。

| 覆盖半径目标 | 所需最小网关天线高度 |
|---|---|
| 1.0 km | 约 6 m |
| 2.0 km | 约 10 m |
| 3.0 km | 约 15 m |
| 5.0 km | 约 22 m |

这张表说明：**限制覆盖的不是几何视距，而是路径损耗与阴影衰落**。这也是为什么本方案把网关塔高定在 15 m（可覆盖约 24 km 视距）、节点立杆定在 4 m——高度取充裕值是为了**压低衰落深度**，而不是因为几何上不够。抬高天线的真实收益在于减少地面反射的相干干涉，以及越过作物冠层。

### 5.4 空中时间与信道占用

LoRa 的空中时间（Time-on-Air）直接决定单节点的信道占用时长，进而决定 TDMA 时隙规划与功耗。

参数：SX1262、BW = 125 kHz、CR = 4/5、显式头、前导 8 符号。

| 扩频因子 | 32 字节空中时间 | 相对倍数 |
|---|---|---|
| SF7 | 72 ms | 1× |
| SF8 | 133 ms | 1.8× |
| SF9 | 246 ms | 3.4× |
| SF10 | 452 ms | 6.3× |
| SF11 | 905 ms | 12.6× |
| SF12 | 1810 ms | 25× |

这张表是后续所有时隙与功耗设计的基础。可以看到 **SF 每提高两档，空中时间约翻两番**：SF7 发 32 字节仅 72 ms，而 SF12 需要 1810 ms，**相差 25 倍**。

因此 SF 的选择是一次「**灵敏度换时间**」的权衡，本方案按现场链路条件自适应：
- 近距节点用 **SF9** 省电
- 远距或遮挡节点升到 **SF12** 保通

### 5.5 私有帧格式设计

本方案采用**私有帧协议而非 LoRaWAN**。原因有三：

1. 私有帧可完全自定义上报内容与压缩方式，避免 LoRaWAN 的固定帧结构开销
2. 无需额外部署 LoRaWAN 服务器与入网流程
3. 微功率法规下自建小规模网络完全合规

**上行数据帧结构**：

| 字段 | 长度 | 说明 |
|---|---|---|
| 前导码 | 2 B | 0xAA 0x55 |
| 节点 ID | 2 B | 网络内唯一地址 |
| 序号 | 2 B | 递增，防重放 |
| 命令字 | 1 B | 0x01=数据上报 |
| 载荷长度 | 1 B | TLV 区字节数 |
| 载荷 | N B | TLV 结构 |
| 传感器状态 | 1 B | 位图，标记各传感器是否故障 |
| CRC16 | 2 B | 整帧校验 |

**载荷 TLV 定义（数据上报类型）**：

| TLV 类型 | 长度 | 内容 |
|---|---|---|
| 0x01 | 2 B | 10 cm 层含水率（0.1% 分辨率） |
| 0x02 | 2 B | 20 cm 层含水率 |
| 0x03 | 2 B | 40 cm 层含水率 |
| 0x04 | 2 B | 60 cm 层含水率 |
| 0x05 | 2 B | 土壤温度（0.1 ℃ 分辨率） |
| 0x06 | 2 B | 电导率 |
| 0x07 | 2 B | 雨量累计 |
| 0x08 | 2 B | 电池电压（mV） |

**设计要点**：

- **序号字段是防重放的关键** —— 网关维护每个节点的最新序号，丢弃重复或回退的报文
- **TLV 结构使载荷可扩展** —— 后续增加水位或土壤 pH 传感器时无需改动帧头
- **传感器状态位图**让网关能区分「数值为 0」与「传感器故障」，避免把故障当成极端干旱。**最后一点在业务上非常重要。**

### 5.6 TDMA 时隙规划

星型拓扑下多个节点共享信道。本方案采用**网关信标同步 + TDMA 时隙分配**，而不是让节点随机竞争发送，原因是随机竞争在节点数量增加后冲突率迅速上升，且节点无法预知何时发送，只能延长接收窗，反而更耗电。

| 时隙 | 时长 | 用途 |
|---|---|---|
| 信标时隙 | 5 s | 网关广播同步与配置 |
| 节点数据时隙 × N | 每节点 3 s | 各节点按 ID 顺序上报 |
| 下行配置窗 | 10 s | 网关下发参数（如采样周期） |
| 空闲保护 | 余量 | 异常事件即时上报 |

**把轮内总占用控制在 160 s（4.4%）有两个好处**：

1. 留下大量空闲时间给异常事件的即时上报（如强降雨触发的加密上报）
2. 网关可以在轮内插入下行配置窗口而不挤占数据时隙

这是低占空比设计的直接体现，也符合微功率设备对占空比的约束精神。

## 6 节点功耗建模与供电设计

### 6.1 功耗模型与计算依据

节点的平均电流由各状态电流与驻留时间加权得出：

```
I_avg = Σ(I_state × t_state) / T_cycle
```

| 状态 | 电流 | 单次时长 | 60 min 周期内占比 |
|---|---|---|---|
| Standby（RTC 保持） | 0.4 µA | 约 59 min | 98.6% |
| 唤醒 + 传感器上电稳定 | 8 mA | 3 s | 0.08% |
| RS485 读数 | 12 mA | 2 s | 0.06% |
| LoRa 发射（+17 dBm） | 118 mA | 0.25 s | 0.007% |
| MCU 运行（处理） | 6 mA | 1 s | 0.03% |
| 传感器升压静态 | 0.1 mA | 5 s | 0.14% |
| **加权平均** | **57 µA** | — | 100% |

**结论**：60 min 周期下平均电流 **57 µA**，理论续航以年计。

### 6.2 扩频因子与发射功率对功耗的影响

| 配置 | 空中时间 | 单次发射电荷 | 相对功耗 |
|---|---|---|---|
| SF7 @ +17 dBm | 72 ms | 8.5 mC | 1× |
| SF9 @ +17 dBm | 246 ms | 29 mC | 3.4× |
| SF12 @ +17 dBm | 1810 ms | 214 mC | 25× |
| SF12 @ +22 dBm | 1810 ms | 249 mC | 29× |

**取舍**：SF12 的功耗是 SF7 的 25 倍，但灵敏度提升约 12 dB（等效覆盖半径翻倍以上）。因此**不要盲目用最大 SF**——应在满足链路余量的前提下取最小可用的 SF。

### 6.3 太阳能供电系统校核

以华北地区为例（日均有效峰值日照 3.5 h）：

| 项目 | 计算 |
|---|---|
| 日均耗电量 | 57 µA × 24 h = 1.37 mAh |
| 系统电压 | 3.7 V（锂电） |
| 日均能耗 | 5.1 mWh |
| 太阳能板需求（含充电效率 70%、3 天自给） | 5.1 × 3 / (3.5 × 0.7) ≈ **6.2 mW** |
| 选用板 | **6 W**（大幅冗余，应对阴雨与污损） |
| 电池容量（7 天自给） | 1.37 mAh × 7 × 1.5 ≈ **14 mAh** |
| 选用电池 | **18650 锂电 2000 mAh**（极端冗余） |

> 实际选型远超理论需求，原因是**野外不可维护性**——一次连续阴雨或积雪覆盖就可能耗尽理论余量。

### 6.4 电池方案对比与低温影响

| 电池类型 | 能量密度 | 低温性能 | 循环寿命 | 成本 | 适用 |
|---|---|---|---|---|---|
| **三元锂（18650）** | 高 | 一般（-20 ℃ 容量降 30%） | 500~800 次 | 中 | ★ 本方案 |
| 磷酸铁锂 | 中 | 好（-20 ℃ 容量降 15%） | 2000+ 次 | 中高 | 高寒优先 |
| 锂亚硫酰氯（ER34615） | 极高 | 好 | 一次性 | 中 | 免维护场景 |
| 铅酸 | 低 | 差 | 300 次 | 低 | 不推荐 |

**低温对策**：
- 电池仓加保温层
- 选用磷酸铁锂（高寒地区）
- 充电控制器带低温保护（0 ℃ 以下禁充）

### 7.1 网关硬件构成

| 部件 | 型号/规格 | 说明 |

### 7.2 数据回传与协议

| 协议 | 用途 |
|---|---|
| **MQTT** | 主回传通道，JSON 载荷 |
| **SL 651** | 对接水文监测平台（如需） |
| HTTP | 备用通道 |

**MQTT 主题设计**：

```
soil/{basin_id}/{node_id}/data      上行数据
soil/{basin_id}/{node_id}/status    节点状态
soil/{basin_id}/gateway/status      网关状态
soil/{basin_id}/{node_id}/cmd       下行配置
```

### 7.3 断网续传机制

野外 4G 信号不稳定是常态，必须设计续传：

1. **本地缓存**：每帧上报数据写入 W25Q128，带时间戳与序号
2. **发送确认**：MQTT QoS1，收到 PUBACK 才标记已发送
3. **断网检测**：连续 3 次发送失败或心跳超时，进入缓存模式
4. **恢复续传**：网络恢复后按时间顺序补传，速率限制避免拥塞
5. **存储管理**：环形缓冲，容量满时覆盖最旧数据并记录丢弃计数

## 8 供电、防雷与野外防护

### 8.1 供电系统设计

- 太阳能板 → 充电控制器（MPPT 或 PWM）→ 锂电 → LDO/DCDC → 各负载
- 传感器与射频**受控供电**（MOSFET 开关）
- 电池电压经分压进 ADC 监测，低于阈值时降低上报频率并告警

### 8.2 防雷与接地

野外设备雷击是主要故障源：

- 天线入口加**气体放电管 + TVS** 两级防护
- 电源入口加**压敏电阻 + TVS**
- RS485 总线加**自恢复保险丝 + TVS**
- 独立接地极，接地电阻 < 4 Ω
- 信号地与功率地单点连接

### 8.3 外壳防护与安装

| 项目 | 要求 |
|---|---|
| 防护等级 | IP66 以上 |
| 材质 | 工程塑料（耐 UV）或不锈钢 |
| 安装 | 立杆，离地 1.5 m 以上防淹 |
| 散热 | 被动散热，避免阳光直射 |
| 防虫 | 透气阀 + 防虫网 |

## 9 软件架构与关键流程

### 9.1 软件分层

```
┌─────────────────────────────────────┐
│  应用层   采样调度 · 数据打包 · 上报   │
├─────────────────────────────────────┤
│  协议层   私有帧格式 · Modbus · MQTT  │
├─────────────────────────────────────┤
│  驱动层   SX1262 · RS485 · ADC · RTC  │
├─────────────────────────────────────┤
│  系统层   RT-Thread Nano（线程/IPC）  │
├─────────────────────────────────────┤
│  硬件层   GD32 / STM32 · 标准外设库   │
└─────────────────────────────────────┘
```

### 9.2 节点主流程

```
上电/唤醒
   │
   ├─ 初始化（时钟、GPIO、外设）
   │
   ├─ 传感器上电 → 等待稳定（3 s）
   │
   ├─ RS485 读取墒情数据（Modbus RTU）
   │
   ├─ 传感器断电
   │
   ├─ 读取电池电压、雨量计数
   │
   ├─ 打包私有帧（TLV）
   │
   ├─ 等待本节点 TDMA 时隙
   │
   ├─ LoRa 发射 → 等待 ACK（可选）
   │
   ├─ 无 ACK → 本地缓存，下次重发
   │
   └─ 进入 Standby，RTC 设定下次唤醒
```

### 9.3 网关主流程

```
初始化（LoRa、4G、文件系统）
   │
   ├─ 广播信标（同步 + 时隙表）
   │
   ├─ 按 TDMA 时隙接收各节点数据
   │
   ├─ 校验（CRC、序号防重放）
   │
   ├─ 写入本地存储（W25Q128）
   │
   ├─ 通过 4G 上报 MQTT
   │
   ├─ 发送失败 → 保持缓存，后台重试
   │
   └─ 循环
```

### 9.4 关键代码骨架

**低功耗主循环**（伪代码）：

```c
int main(void)
{
    board_init();          /* 时钟、GPIO、外设 */
    sensor_power_off();    /* 非采样期断电 */
    lora_init();
    rtc_alarm_set(SAMPLE_PERIOD_S);

    while (1)
    {
        /* 进入 Standby，等待 RTC 闹钟或雨量计脉冲唤醒 */
        pmu_to_standby(WFI_CMD);

        /* ---- 唤醒后执行 ---- */
        sensor_power_on();
        delay_ms(3000);                  /* 等待传感器稳定 */

        if (sensor_read_modbus(&data) == OK)
            build_frame(&frame, &data);  /* 打包 TLV */
        else
            frame.status |= SENSOR_FAULT;

        sensor_power_off();              /* 立即断电省电 */

        lora_send_frame(&frame);         /* TDMA 时隙内发送 */

        if (!lora_wait_ack(2000))
            cache_store(&frame);         /* 失败入缓存 */

        iwdg_feed();                     /* 喂狗 */
    }
}
```

**RS485 方向切换**（关键：等 TC 而非 TXE）：

```c
void rs485_send(const uint8_t *buf, uint16_t len)
{
    RS485_DE_HIGH();                     /* 切发送 */
    for (uint16_t i = 0; i < len; i++) {
        while (!(USART->SR & USART_SR_TXE));
        USART->DR = buf[i];
    }
    /* ★ 必须等 TC（发送完成），不能只等 TXE（发送寄存器空） */
    while (!(USART->SR & USART_SR_TC));
    RS485_DE_LOW();                      /* 切回接收 */
}
```

> **坑点**：只等 `TXE` 就切方向，最后一个字节会被截断。这是 RS485 最常见的 bug。

### 9.5 可靠性与异常处理

| 异常 | 检测 | 处理 |
|---|---|---|
| 传感器无响应 | Modbus 超时 | 重试 3 次，失败标记故障位，仍上报 |
| 电池欠压 | ADC 监测 | 降低上报频率，标记告警 |
| LoRa 发送失败 | 无 ACK | 本地缓存，下次重传 |
| 4G 断网 | 心跳超时 | 进入缓存模式，恢复后补传 |
| 程序跑飞 | IWDG | 自动复位，复位原因记录 |
| 数据异常 | 范围校验 | 丢弃越界值，标记可疑 |

## 11 结论

本方案针对河流流域墒情监测「带状分布、无电无网、低空链路」三个特征，给出了完整的技术路径：

1. **架构** —— 星型 LoRa 私有网 + 网关公网回传，拒绝让电池节点承担 Mesh 转发
2. **选型** —— 节点 GD32L233（Stop < 2 µA）、网关 GD32F303、射频 SX1262（接收电流仅 4.6 mA）
3. **覆盖** —— 余量预算法反解，单跳设计半径 2.0 km，而非按自由空间公式虚报
4. **功耗** —— 60 min 周期平均 57 µA，续航以年计；核心是占空比控制与受控供电
5. **可靠** —— 序号防重放、状态位图区分故障与零值、断网续传、独立看门狗

**关键取舍分歧**：本方案明确不采用 Mesh，因为转发会让节点从 µA 级跃升到 mA 级，续航从年降到月。这一取舍在「电池节点 + 长续航」场景下是刚性的。

方案的量化结论均可通过可复算脚本复核，硬件参数来自厂商公开规格，标准依据需在设计交底前核对现行版本。
